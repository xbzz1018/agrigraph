# 代表性问题与解决方案

本文件只记录当前精简项目中真正影响农业知识服务质量的工程问题，不把日志字段或内部实现细节当作成果。

## 1. 文本和图片输入难以复用同一条知识链

**问题：** 视觉模型容易直接给出病名，文本问答和图片诊断分别维护两套路由，结果难以统一评测。

**根因：** 图片结果没有先收敛为稳定的农业领域结构。

**解决：** Qwen3-VL-Flash 只输出 `VisionObservation`（作物、部位、可见症状、质量提示），再转换为 `AgricultureQuery`，与文本问题共用 BM25、Neo4j 和证据回答流程。视觉模型负责观察，知识库负责候选解释，不宣称直接确诊。

**验证：** 图片和文本接口统一返回候选实体、引用、图谱关系和防治选项；视觉结构化字段有独立测试。

## 2. 会话上下文可能污染事实依据

**问题：** 多轮追问需要记忆，但历史对话不能被当成农业事实引用。

**根因：** 上下文和外部知识如果共用证据结构，回答层无法区分来源可信度。

**解决：** 会话上下文只作为问题理解输入；Answer 只能消费 Elasticsearch 和 Neo4j 证据；Evidence Check 只校验外部证据 ID，最终引用不包含会话内容。

**验证：** 空知识库和多轮会话测试确认不会因有历史消息而把回答标记为有知识依据。

## 3. 公开农业资料包含具体用药参数

**问题：** 公开资料常同时包含药剂名称、浓度、倍液、亩用量和混配说明，直接索引或生成会产生不合适的使用建议。

**根因：** 原始 `controlMeasures` 是面向资料阅读的长文本，不适合作为对外回答字段。

**解决：** 原始数据保持只读；导入阶段通过别名配置抽取有效成分、生物防治和农业防治名称，不把用药原句写入 ES/Neo4j；回答完成后再过滤百分比、倍液、面积用量、混配、频次和安全间隔。用户追问具体用量时只返回登记标签和农技人员提示。

**验证：** 防治抽取和回答边界测试覆盖典型中文表达，剂量信息泄漏率要求为 0。

## 4. 可选组件与当前运行依赖混淆

**问题：** 旧记录写着已移除 Redis 和 Reranker、只需 Elasticsearch 与 Neo4j，与当前代码和启动脚本不符。

**解决：** 当前业务链路使用 Elasticsearch BM25、症状/条件问题的可选 Reranker、Neo4j、固定 LangGraph、SQLite 与 Vue。Redis 短期记忆和 PostgreSQL/ES 长期记忆属于上下文层；外部 Embedding 只服务记忆检索，不改变文档 BM25 的证据角色。不恢复对象存储、治理审批或额外自由编排 Agent。

**验证：** 架构、运行手册和首页统一列出 Elasticsearch、Neo4j、PostgreSQL、Redis 的启动依赖；上下文仍不进入事实引用。

## 5. 重排执行结果被固定的 BM25 标记覆盖

**问题：** SSE 固定报告 `bm25`，健康检查也缺少配置策略与实际运行的区别。

**解决：** 健康检查报告配置策略；运行结果从文档证据汇总 `none / bm25 / bm25_rerank`，附 `degraded` 和稳定原因码。重排 HTTP 失败/空结果回退 BM25 顺序；外部响应正文不进入事件。前端事件类型及 `complete` 的直接载荷同步处理。

**验证：** [检索契约测试](../../backend-python/tests/agents/test_retrieval_contract.py)覆盖服务边界、SSE/最终结果与 OpenAPI；[离线案例](../../examples/evidence-case/README.md)通过完整工作流检查五条路径。它们不代替真实服务验收。
