# 代表性问题与解决方案

本文件只记录当前精简项目中真正影响农业知识服务质量的工程问题，不把日志字段或内部实现细节当作成果。

## 1. 文本和图片输入难以复用同一条知识链

**问题：** 视觉模型容易直接给出病名，文本问答和图片诊断分别维护两套路由，结果难以统一评测。

**根因：** 图片结果没有先收敛为稳定的农业领域结构。

**解决：** Qwen3-VL-Flash 只输出 `VisionObservation`（作物、部位、可见症状、质量提示），再转换为 `AgricultureQuery`，与文本问题共用 BM25、Neo4j 和证据回答流程。视觉模型负责观察，知识库负责候选解释，不宣称直接确诊。

**验证：** 图片和文本接口统一返回候选实体、引用、图谱关系和防治选项；视觉结构化字段有独立测试。

## 2. 会话上下文可能污染事实依据

**问题：** 多轮追问需要记忆，但历史对话不能被当成农业事实引用。

**根因：** 上下文和外部知识如果共用证据结构，回答层无法区分来源可信度。

**解决：** 会话上下文只作为问题理解输入；Answer 只能消费 Elasticsearch 和 Neo4j 证据；Evidence Check 只校验外部证据 ID，最终引用不包含会话内容。

**验证：** 空知识库和多轮会话测试确认不会因有历史消息而把回答标记为有知识依据。

## 3. 公开农业资料包含具体用药参数

**问题：** 公开资料常同时包含药剂名称、浓度、倍液、亩用量和混配说明，直接索引或生成会产生不合适的使用建议。

**根因：** 原始 `controlMeasures` 是面向资料阅读的长文本，不适合作为对外回答字段。

**解决：** 原始数据保持只读；导入阶段通过别名配置抽取有效成分、生物防治和农业防治名称，不把用药原句写入 ES/Neo4j；回答完成后再过滤百分比、倍液、面积用量、混配、频次和安全间隔。用户追问具体用量时只返回登记标签和农技人员提示。

**验证：** 防治抽取和回答边界测试覆盖典型中文表达，剂量信息泄漏率要求为 0。

## 4. 技术组件过多导致定位不清

**问题：** 旧实现同时维护向量检索、混合融合、Reranker、对象存储、组织标签和治理流程，农业知识主线不突出，运行依赖也更难复现。

**根因：** 把可选增强能力误当成项目核心能力。

**解决：** 收缩为 DeepSeek + Qwen3-VL、Elasticsearch BM25、Neo4j、LangGraph、SQLite 和 Vue 3；移除 Embedding、RRF/MMR、Reranker、MinIO、Redis、治理审批和额外 Agent。保留图谱是因为它直接承担农业关系组织和解释，而不是为了堆叠技术名词。

**验证：** 新建库 Alembic、Ruff、后端测试、前端 typecheck/build 和 Compose 配置均通过；运行只需 Elasticsearch 与 Neo4j。
